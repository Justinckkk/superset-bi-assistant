# v2事件速查（探索结果：未核准口径）

只用于已授权的201、170、9212、209。全名为 `neo_game_v2.g<号>_game_data`；先用ADB CURRENT_DATE换算最近7个完整日常量，执行单表 `SELECT g_event_name, COUNT(*) AS n … WHERE g_time >= '起日' AND g_time < '止日' GROUP BY g_event_name`，再用顶层 AND 指定事件。宽表不能SELECT *。下面是候选与有界证据，不是全部历史枚举；物理列和类型先读数据集元数据，未知枚举不猜。

## 通用来源与单位
- 专用 `recharge_log`：`product_id` 商品、`order_id` 订单、`amount` 美分；真实充值 `recharge_type=1`，金额除100为美元。`COUNT(*)` 是记录笔数，不保证订单去重或商品件数；`product_amount` 是否存在、有值逐游戏核实。
- 专用 `login_or_logout_log` 是加工的账号/日活跃小表，不是全量每次登入登出；完整在线从宽表同名事件取 `online_duration`，不是累计 `duration`。登录日界线按游戏与服核对，不统一擅改时区。
- 专用 `role_creation_log_first` 是账号首次创角，不等于final_data按账号创建日登录定义的cohort。`user_log_last` 未开放：不是历史快照，170账号非唯一、209近期空。
- `currency_log` / `item_log` 的 `amount` 是游戏资源变更数量，不除100；默认 `action` 为获得/消耗，具体枚举以产品证据优先。ID未命中保留原ID，不编名称。

## 森国201
- `quest_log`：`task_id` 任务、`action` 动作；已有样本动作不能当完整枚举，完成码待确认，不能直接把2当完成。
- `battlefield_log`：`stage_id` 关卡候选；`type`、`result` 等物理映射和成功语义须按样本核对，不凭布尔值猜胜负。
- `levelup_log`：`level_before`、`level`；R6窗口 `level_after` 全空，不能依赖它计算升级后等级。
- `currency_log` / `item_log`：`currency_id` / `item_id`、`action`、`amount`、`total_before/after`、`level_one/two/three_reason`；货币与物品ID不互换，三级原因不套一二级对照，BI对账要排除本游戏内部号。
- `shop_log`：`product_id` 与商品数组在 `g_event_content`；不能套旧源字段路径或把两个数组交叉展开。`recharge_extra_log` 仅补充商品映射，金额/件数/充值性质不能假定有值，订单关联先去重。
- 细节：`reference/neocraft-data/sql/references/games/201/events.yaml`、`event_field_samples.md`、`lookups/warehouse_mapping.md`；近期核查见 `reports/R6.md`，旧库空窗见 `reports/R5.md`，不把旧库结论套到v2。

## 风之大陆170
- `quest_log`：`task_id`、`action`；任务拓扑、完成动作需业务确认，不照搬201。
- `battlefield_log`：`stage_id`、`level` 等以元数据及窗口核实；R6关卡字段有值。`progression_log` 是资料候选但R6窗口未返回，不承诺近期存在。
- `levelup_log`：`level_before`、`level_after`、`level` 有近期证据，不能把账号和角色混用。
- `currency_log` / `item_log`：资源ID、动作与数量；原因及名称按本游戏配置版本。`shop_log` 的 `shoptype` 决定 `product_id` 对应配置，商品ID不是物品ID。
- `ah_log`：`buy_type`、动作组合需读拍卖证据；`buy_type=2` 包含上架/下架/收取，不是成交条件。专用充值缺 `product_amount`，禁止销量=行数的默认假设。
- 细节：`reference/neocraft-data/sql/references/games/170/observed_events.json`、`source_event_fields.json`、`current_sample_evidence.md`、`auction_profile.md`、`cohort_acceptance.md` 及 `reports/R6.md`。

## 真三国无双9212
- `battlefield_log`：`target_id`、`type`、`result`、`difficult`、`sweep`、`sub_type`；源 `battle_id/battle_type` 映射到目标字段，不直接使用源别名拼SQL。
- `baihua_log`：`curr_layer` 层数候选；先盘点，再核实专属字段语义。
- `login_or_logout_log`：`level` 仅事件时等级；该游戏活跃包含登入与登出，不能过滤只登入；`login_or_logout=2` 是登出。R6无通用任务ID、关卡ID及升级前后契约，不套其他游戏 `task_id/stage_id/levelup_log` 模板。
- `currency_log` / `item_log`：`currency_id` / `item_id`、`amount`、`action`、三级原因；名称共用Items对照但原因表分开。充值数字编码与平台商品字典命名空间可能不同。
- 细节：`reference/neocraft-data/sql/references/games/9212/events.yaml`、`client_schema.yaml`、`login_day_boundary.md`、`current_sample_evidence.md` 和 `reports/R6.md`。

## 万灵209
- `quest_log`：`task_id`、`action` 有近期证据；只有基础拓扑与事件盘点，完成码未核准，不因列有值就假定业务语义。
- `battlefield_log`：事件近期存在，但R6 `stage_id` 全空；`battle_id/target_id` 映射待确认，不能宣称可算关卡漏斗。
- `levelup_log`：`level_before`、`level` 有值，没有 `level_after` 物理列。
- `currency_log` / `item_log`：按通用资源模板加本游戏元数据核实；`shop_log` 是游戏内商城，不替代现金订单。`heartbeat_log`、`rank_log` 等仅作为盘点候选，不把单日盘点当历史全集。
- 细节：`reference/neocraft-data/sql/references/games/209/tables.yaml`、`reference/neocraft-data/sql/references/catalog/event_inventories/209.json`、`reference/neocraft-data/sql/references/schemas/common/` 和 `reports/R6.md`；R5旧库结果仅作来源差异证据。
