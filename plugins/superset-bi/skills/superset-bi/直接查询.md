# 直接查询：未核准口径

仅当核准数据集无法回答探索问题且工具列表有 `execute_sql` 时使用。DAU、留存、LTV 等标准指标仍必须用核准数据集；直接查询结果一律标明“未核准口径”。原始事件表不用于建图、建看板，不修改数据集。

先读授权数据集的 description：“原始_<游戏简称>_事件表”是说明标签，物理数据集 table_name 仍为真实表名（如 `g201_final_data`），不要把中文标签当 SQL 表名。只能查已登记且自己有游戏权限的表。

## 可用来源

游戏号仅201、170、9212、209，逐游戏授权；SQL始终使用完整schema.table。`neo_game.g<号>_final_data` 保留BI复现；完整事件探索使用 `neo_game_v2.g<号>_game_data`，现金订单用v2 `recharge_log`，加工活跃用v2 `login_or_logout_log`，首次创角用v2 `role_creation_log_first`。v2数据集描述为“原始_<游戏简称>_<用途>”。`user_log_last` 未登记，不能查询；默认连接schema仍是neo_game，不会自动推断v2。

v2真实充值必须 `recharge_type=1`，`SUM(amount)/100.0` 为美元；游戏货币/道具流水数量不除100，记录笔数不等于商品件数。final_data与v2在cohort、真实付费过滤、去重、日界线等方面可能有差异，不将新来源结果当作已核准BI数字。

## 查询规则和改错

- 单条 SELECT，可含普通 CTE、UNION、子查询；每个实际读取表实例在自己的查询块内需要原日期列常量双界，最多 92 天。`neo_game.g<号>_final_data` 用 `g_date_day`（DATE），允许 BETWEEN、相等、IN；`neo_game_v2` 的四类表用 `g_time`（TIMESTAMP），只接受有界比较或 BETWEEN，不能靠相等/IN作为范围。
- 推荐 `g_time >= '2026-10-01' AND g_time < '2026-11-01'`（31天）；也接受日期时间常量。DATE列相应换成 `g_date_day`。不以 OR、DATE(g_time)、DATE(g_date_day)、外层过滤替代每个表自己的范围。保守拒绝 Jinja、动态日期及递归 CTE。
- `game_data` 宽表在同一查询块顶层 AND 中必须有 `g_event_name = '事件名'` 或 `g_event_name IN ('事件名',…)`。禁止 `SELECT *`、`别名.*`；`COUNT(*)` 可用。事件盘点是唯一例外：单表、只投影事件名和COUNT(*)、只按事件名分组、最多7天。先读 `事件速查.md`，做盘点再查具体事件，不猜事件值。
- 先按天/商品/渠道聚合再取数；最多 5000 行、60 秒，客户端传更大 timeout 也会压到 60。缺失/过大 LIMIT 自动改写；达到行数上限或 MCP 提示截断时，不把部分结果当总量，应缩小范围或加强聚合。
- 被拒时按中文原因补齐每张表自己的范围、缩到 92 天内、改用登记表；无权限找管理员，不绕过。更长历史按小窗分段，去重人数等不可直接跨段相加。
- 今天通过 `SELECT CURRENT_DATE` 取 ADB 北京日期，再换算为常量边界，不用本机日期。
- 原始表含内部号和原始重复记录，不自动继承核准数据集排除/去重/用户类型口径；事件条数不是销量，账号不是角色，空值/枚举含义不猜测。报告和日志不得保存用户明细/原始业务数值。

## 事件表 31 列

以下31列仅描述 final_data；v2列以所选物理数据集元数据为准，不能假定同构。

未确认的 ETL 属性只描述用途，不猜测其原始时间单位或枚举。

| 字段 | 含义与边界 |
| --- | --- |
| g_primary_key | ETL 行键；不假设等于业务订单去重键 |
| g_event_name | 事件名；当前 final_data 核准使用登录登出、充值两类 |
| g_create_time | 入库/处理时间，不替代业务事件日 |
| g_date_day | 事件业务日期/分区日；直接查询强制范围列 |
| g_distinct_id | 采集侧主体标识，不等同账号/角色 |
| g_time | ETL 事件时间，当前表为 timestamp；不当作整数时间戳 |
| g_date | ETL 日期属性，与 g_date_day 的用途区别需核对 |
| g_role_time | 角色创建时间属性，不是账号创建时间 |
| g_role_date | 角色创建日期属性 |
| g_account_time | 账号创建时间属性 |
| g_account_date | 账号创建日期；cohort 按账号而非角色创建日 |
| g_neo_type | ETL/来源分类，枚举需字典确认 |
| g_country | 国家/地区维度；沿用已核准映射，不猜 IP/商店来源 |
| group_id | 区服组/大区维度 |
| platform | 平台维度，枚举以字典为准 |
| event_time | 原始上报事件时间；历史规范常用秒，当前表单位需核验 |
| channel | 渠道维度 |
| account | 账号标识；不把原始 ID 写进报告/日志 |
| device_model | 设备型号 |
| device_brand | 设备品牌 |
| device_os_version | 系统版本 |
| client_version | 客户端版本 |
| server | 服务器维度 |
| role_id | 角色标识，不等于 account |
| level | 事件发生时等级，不是必然最新快照 |
| language | 语言维度 |
| role_name | 角色名；用户级明细不写报告/日志 |
| login_or_logout | 登录/登出类型；枚举先确认 |
| amount | 原始充值金额；当前201、209按 amount/100.0 换算美元，仅充值事件计入；新游戏读各自说明 |
| product_id | 商品标识；空值不表示免费，事件行数不等于商品数量 |
| vip_level | 事件时 VIP 等级属性 |
