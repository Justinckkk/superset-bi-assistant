# 分析问法归类（由问题清单去案例化整理）

先选入口，再取最少的数据；本文件是分析结构，不是已发布功能清单。

| 主题 | 建议先问/先看 | 不能直接推断 |
|---|---|---|
| 新增、留存 | 游戏、创建窗、天龄、渠道、成熟周期；核准留存 | 安装=新增，未成熟=零 |
| 激活、技术质量 | SDK/下载/登录链路、设备主体；公司BI的机型留存/内存流失 | 技术相关性=故障导致流失 |
| 关卡、养成 | 进入/完成/失败、最高进度、角色/账号、观察窗；可用试行主题优先 | 完成热度序=剧情拓扑，进度率=因果 |
| 付费结构 | 销售、分层、首充分别回答，声明固定付费窗口和内部号处理 | 窗口首笔=历史首充，记录笔数=件数 |
| 活动、版本 | 活动日历、可比前后窗口、参与资格；拆充值和资源消耗 | 同期涨跌=活动增量 |
| 经济、资源 | 同币种期初、获得、消耗、期末，原因映射先核实 | 净消耗=毛消耗，快照按行累加 |
| 社交、玩法 | 参与主体、资格、次数与人数；只读事件探索 | 参与人群留存差=玩法因果收益 |
| 渠道、投放 | 归因、时区、币种、成本来源先对齐；缺成本就说明缺口 | 运营LTV=广告LTV，流水=ROI |
| 预测、回本 | 区分成熟实测、假设、外推；索取成本与情景输入 | 核准历史数字可直接当预测 |
| 用户研究 | 问卷/样本、招募偏差、行为证据分开 | 自报体验=全体玩家事实 |

用户只问“最近留存怎么样”且游戏不明时先追问游戏；只说“真三”先确认9212。缺资格、设备映射、任务完成语义时先指出缺口，不凑漏斗。不输出账号名单；只给聚合。
